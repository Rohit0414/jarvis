Practical outcomes

Clear stock decisions, not another report.

Buy only what is needed

Demand minus stock minus incoming supply.

Niyu Forecast checks demand, stock, incoming supply, safety stock, lead time, MOQ, and order multiples. If the forecast says 120 units may be needed, you already have 50, and 30 are incoming, it recommends only the remaining gap.

Move before buying

Use available stock from another warehouse.

If Delhi needs 40 units and Mumbai has 25 spare units, the module can suggest moving 25 first, then buying the remaining 15 if needed.

Transfer + buy split

Real problems often need two actions.

Sometimes the right answer is: move what you already have, then buy only the gap. Niyu Forecast supports this directly with split recommendations.

Warehouse-level planning

A product can be healthy overall and short locally.

Recommendations are created by warehouse, so planning is closer to actual operations and not just product-level totals.

Lead-time planning

Plan cargo-ready and receipt dates.

For simple suppliers, use one lead-time number. For importers and manufacturers, split it into cargo-ready days and transit days. Example: 20 + 35 = 55 total lead-time days.

Forecast reason

Know why the recommendation exists.

Each action line can show the model used, selection reason, guardrail applied, and confidence. Buyers can see whether the product was treated as regular demand, intermittent demand, limited history, or dormant.

Product manual

How to use Niyu Forecast.

1. Install the module

Install the module in Odoo. Open Inventory → Settings. Find the Niyu Forecast section. Enter your API key. Save settings. Click Run Initial Sync.

2. Run your first forecast

Go to Niyu AI → Run Sync Now. Start a manual forecast. After completion, open Niyu AI → Planning Overview.

3. Review Action Lines

Use Action Lines as the main worklist. Common actions: buy now, transfer now, transfer + buy, setup needed, watch, and ignored.

4. Create RFQs

Open a buy action line and click Create RFQ. The module creates or updates a draft RFQ and links it back to the action line.

5. Create Planning Rules

Use rules when a product, category, warehouse, or vendor needs special behavior: safety stock, days of stock, lead time, MOQ, multiples, incoming PO behavior, and schedule profile.

6. Use split lead time

Set Lead Time Mode = Cargo Ready + Transit. Enter Cargo Ready Days and Transit Days. Example: 20 + 35 = 55 total lead-time days.

7. Use Purchase Schedule Profiles

Create profiles such as Import - 3 Monthly Batches. Set schedule mode, batch count, interval days, and split method. Assign the profile to a Planning Rule.

8. Bulk update planning rules

Upload CSV rules for large catalogs. Use operation=deactivate to deactivate rules. Use operation=clear to clear lead time and schedule settings.

9. Use lead-time learning

Enable it in Inventory Settings, then go to Niyu AI → Analyze Lead Times. Review suggestions before applying them.

10. Exclude archived products

Enable Exclude Archived Products in Settings. Archived products will not be sent for new forecasting and can be marked ignored in planning.

FAQ

Everything you need to know.

✶ Does Niyu Forecast work with Odoo Community?

Yes. It is designed to work with Odoo Community.

✶ Does it work with Odoo Enterprise and Odoo.sh?

Yes. It works with Odoo Enterprise and Odoo.sh if the instance can connect to the Niyu forecasting server.

✶ Does it work on on-premise Odoo?

Yes. On-premise Odoo is supported if outbound access to the forecasting server is allowed.

✶ Do I need an API key?

Yes. The API key connects your Odoo database to the Niyu forecasting and planner server. To get one, email info@niyulabs.com.

✶ Is the module free?

Yes. There is a Free Lifetime plan with 20 SKUs, 1 automatic forecast per day, 1 manual forecast per day, and a 30-day forecast horizon.

✶ Why are there paid plans?

Forecasting runs on Niyu's server. Paid plans cover server processing, forecasting jobs, temporary result storage, and support.

✶ Do you store my sales history permanently?

No. Sales history is used for forecast processing. Forecast result payloads are temporary in the backend design.

✶ What data is sent?

The module sends data needed for forecasting and planning, such as product demand history and warehouse context. Customer names are not needed for forecasting.

✶ Can it suggest transfers?

Yes. If another warehouse has available stock, the module can suggest internal transfer before buying.

✶ Can it suggest both transfer and buy?

Yes. It can suggest transferring available stock and buying the remaining quantity.

✶ Can I split purchases?

Yes. Use Purchase Schedule Profiles to split one suggested buy into multiple planned batches.

✶ Does it replace Odoo reordering rules?

It does not need to replace them immediately. You can use Niyu Forecast as a smarter planning layer for products where normal reorder rules are not enough.
