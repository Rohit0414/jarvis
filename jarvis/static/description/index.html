What does this connector do?

It connects Odoo → S3 → Amazon Redshift so your Odoo data becomes analytics-ready tables in Redshift.

🚀 Export Any Model

Export any Odoo model (standard or custom), for example:

  • Sales Orders, Invoices, Customers
  • Products, Inventory, Purchase
  • Custom models from your modules

🔁 Incremental (New + Changed)

It exports only new rows and updated rows using a cursor (like write_date + id). This saves time, cost, and avoids duplicate rows.

⚡ Fast Loading with S3 COPY

Instead of slow row-by-row inserts, it uploads a compressed CSV to S3 and uses Redshift COPY for high-speed ingestion.

⏱ Auto Export (Schedule)

Enable Auto Export and choose an interval. The connector resumes from the last cursor. It runs in batches and stops safely when the time limit is reached.

Why Redshift?

Redshift is built for analytics at scale. Use it for BI dashboards, finance reporting, cohort analysis, and large joins that are slow in OLTP databases.

How it works (Odoo → S3 → Redshift)

No manual SQL needed. The connector handles staging, COPY, and MERGE.

🪃
1) Upload to S3

Odoo creates CSV.GZ and uploads to your bucket

📥
2) COPY to staging

Redshift reads that S3 file using an IAM Role

🔁
3) MERGE to final

Updates existing rows and inserts new rows

🧹
4) Cleanup + Cursor

Drops staging & saves last_sync/last_id for next run

Where is the data stored?
  • Final analytics table is in Redshift (Query Editor shows it).
  • S3 files are usually temporary (optional keep/delete).
  • Staging tables exist only during load, then are dropped.
Why you may not see files in S3?

By default, many setups delete S3 files after COPY to reduce storage and keep data private. If you want to keep them, enable a “Keep S3 files” option (or ask your admin to disable auto-delete).

Pro Tip
Test first with a smaller model like res.partner or product.product, then move to large tables.
AWS Setup

Step 1: Create S3 Bucket + IAM Permissions

You need an S3 bucket where Odoo uploads batches, and an IAM Role so Redshift can read those files for COPY.

1A) Create an S3 bucket
  1. Open AWS Console → search S3
  2. Click Create bucket
  3. Choose a name (example: niyu-redshift-odoo-exports)
  4. Pick a region (example: ap-south-1)
  5. Keep Block all public access = ON
  6. Create bucket
📌 Where to find your bucket later?
AWS Console → S3 → Buckets → click your bucket name
1B) Create IAM Role for Redshift COPY
  1. AWS Console → search IAM → Roles
  2. Click Create role
  3. Trusted entity: AWS service
  4. Use case: select Redshift (or Redshift Serverless)
  5. Attach policy: allow s3:GetObject on your bucket prefix
  6. Create role and copy its Role ARN
📌 Where to find Role ARN?
AWS Console → IAM → Roles → click role → copy ARN from Summary

Required IAM Permissions (simple)

You normally need two permission sets: (1) Odoo uploader to write files to S3, and (2) Redshift COPY role to read files from S3.

(A) Odoo uploader policy (PutObject)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListBucketPrefix",
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME",
      "Condition": {"StringLike": {"s3:prefix": ["odoo_exports/*"]}}
    },
    {
      "Sid": "WriteObjects",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:AbortMultipartUpload",
        "s3:ListBucketMultipartUploads",
        "s3:ListMultipartUploadParts"
      ],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/odoo_exports/*"
    }
  ]
}
(B) Redshift COPY role policy (GetObject)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadObjectsForCopy",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:GetObjectVersion"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/odoo_exports/*"
    },
    {
      "Sid": "ListBucketForCopy",
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME",
      "Condition": {"StringLike": {"s3:prefix": ["odoo_exports/*"]}}
    }
  ]
}
If you enable “Delete S3 file after COPY”, add s3:DeleteObject permission to the Odoo uploader policy.
Redshift Setup

Step 2: Create Redshift (Serverless) + Get Host/Namespace

You will copy the Workgroup endpoint (host), choose a database name, and ensure the IAM Role is associated so COPY can read from S3.

2A) Create Redshift Serverless (recommended)
  1. AWS Console → search Amazon Redshift
  2. Choose Redshift Serverless
  3. Create Namespace and Workgroup
  4. Set admin user/password (or use existing)
  5. Ensure network allows connection (VPC / security group)
Meaning of words
Namespace = logical container for databases & users
Workgroup = compute + endpoint you connect to (host)
2B) Where to find Host + Database
  • Host (endpoint): Redshift Console → Serverless → Workgroups → click your workgroup → copy Endpoint
  • Database name: often dev by default (or what you set)
  • Port: typically 5439
  • Username/Password: from your Redshift admin/db user
Example host format
your-workgroup-id.account-id.region.redshift-serverless.amazonaws.com
⚠ Important: Associate IAM Role with Workgroup (COPY permission)
If COPY fails with “role is not associated”, go to: Redshift Serverless → Workgroup → Permissions / IAM roles and attach the same Role ARN you use for COPY.

Odoo Setup

Step 3: Configure the Connector in Odoo

Go to: Settings → Amazon Redshift Connector (or your module menu). Fill Redshift + S3 settings.

Redshift fields to fill
  • • Host: Workgroup endpoint
  • • Port: 5439
  • • Database: usually dev
  • • User / Password: Redshift DB user
  • • Schema: e.g. odoo
  • • COPY IAM Role ARN: role that can read S3
S3 fields to fill
  • • Bucket: your bucket name
  • • Region: same as bucket region
  • • Prefix: e.g. odoo_exports/
  • • Keep S3 files: ON to keep, OFF to auto-delete after COPY
  • • Compression: CSV.GZ (recommended)
AWS credentials for S3 upload (important)

Odoo must be able to upload the CSV to S3. Choose ONE method:

Option A (Recommended): Instance Role
If Odoo runs on EC2, attach an IAM Role to the EC2 instance. No access keys stored in Odoo.
Option B: Access Key + Secret
Provide AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY (best via server env vars). Use the “Odoo uploader policy” shown earlier.
If you ever see error NoCredentialsError: Unable to locate credentials, it means this upload credential is missing.

Step 4

Create an Export in Odoo

Pick model and fields. Run now or schedule it.

What is an Export?

An Export is a saved “sync definition” (table name + model + fields + filter + schedule). You can create many exports (Sales Orders, Invoices, Customers, etc.).

Common fields
  • • Export Name: final Redshift table name (example: sale_order)
  • • Odoo Model: which model you export
  • • Columns: fields you want in Redshift
  • • Domain Filter: optional, export only some rows
  • • Batch Size: example 50,000 rows
  • • Time Limit: stop safely and resume next run
Domain filter examples

Only confirmed Sales Orders:

[('state','=','sale')]

Only one company + amount > 1000:

[('company_id','=',1),('amount_total','>',1000)]
What happens on Run?
  • Fetches one batch from Odoo
  • Uploads CSV.GZ to S3
  • Creates staging table
  • Runs Redshift COPY
  • Runs MERGE to final table
  • Saves cursor (last_sync + last_id)

Step 5

Check Data in Redshift Query Editor

After export, the table appears in your Redshift database and you can query it.

Where to open Query Editor
  1. AWS Console → Amazon Redshift
  2. Left menu → Query editor v2
  3. Connect to your Workgroup
  4. Select your database (e.g., dev)
  5. Run a query
-- Quick checks

SELECT COUNT(*) FROM odoo.sale_order;
SELECT * FROM odoo.sale_order LIMIT 50;
Table naming
Your Export Name becomes your Redshift table name. Example export res_partner → table odoo.res_partner.

Automation

Auto Export + Time Limit Resume (No Thread Explosion)

The connector runs in batches. If a time limit is reached, it stops safely and continues next run from the saved cursor.

How resume works
  • Every batch updates last_sync and last_id
  • On next run, it fetches the next batch using that cursor
  • If time limit hits, it ends the request cleanly (no partial corruption)
  • Auto Export (cron) triggers next run later
Recommended settings
  • Batch size: 25k–50k (start with 10k for first test)
  • Time limit: 60–120 seconds
  • Auto export interval: 10–30 minutes
  • One export at a time: avoid running many heavy exports in parallel
Avoid hitting Odoo worker/thread limits
Keep exports short (time limit) and let cron resume later. Do not run 20 exports at the same minute. Use staggered intervals (example: Sales every 15 min, Partners every 30 min).

Security

Security Best Practices

Keep your bucket private and use least-privilege IAM roles.

✅ S3 bucket
  • Block all public access = ON
  • Use a prefix like odoo_exports/
  • Enable bucket versioning (optional)
  • Enable lifecycle rule to auto-delete old files (if keeping files)
✅ IAM roles
  • Separate roles: uploader vs COPY role
  • Limit permissions to bucket + prefix only
  • Avoid storing access keys in Odoo when possible
  • Prefer EC2 Instance Role / managed credentials
Data privacy note
If you keep S3 files, treat the bucket as sensitive. It contains raw exported data. If you delete after COPY, S3 stays clean and private.

Fix Problems (Most Common)

Almost always: missing permissions or wrong endpoint.

Error → Fix
1) NoCredentialsError: Unable to locate credentials
Odoo cannot upload to S3. Add AWS credentials using Instance Role (recommended) or Access Key/Secret.
2) Role is not associated to cluster/workgroup
The IAM Role ARN used in COPY must be attached to Redshift. Go to Redshift Serverless → Workgroup → Permissions / IAM roles and attach the Role.
3) S3 AccessDenied during COPY
The COPY role is missing s3:GetObject or the bucket policy blocks access. Confirm the role has permission to arn:aws:s3:::YOUR_BUCKET/odoo_exports/*.
4) Can’t connect to host / timeout
Network issue. Redshift workgroup is inside a VPC. Ensure Odoo server can reach it (VPC routing / security group / public accessibility).
5) Time limit reached (not an error)
This is expected for large tables. The connector stopped safely and saved cursor. Run again or let Auto Export resume.

FAQ

Will it duplicate my rows?

No. It uses staging + MERGE to update existing rows and insert new rows.

Do I need SQL knowledge?

No. You only select model + columns in Odoo. SQL is optional for analytics later.

Will I always see S3 files?

Not always. Many setups delete after COPY. Enable “Keep S3 files” if needed.
